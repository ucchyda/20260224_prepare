- 本設計書は、`/Users/rikuuchida/Documents/20260224_prepare` 配下の会議エージェント運用を、初見者が一読で理解できるように統一整理する。
- 対象は取締役会会議の2役割です。

- 役割B（会議中）: `InMeetingCriticAgent` を中心に、発言の根拠・論理・期限・責任を監査し、Teams投稿に適した確認質問へ変換する。

## 2. エージェントチーム構成

### 2.1 コア層（全体制御）

| エージェント | 役割 | 入力 | 出力 | 判断トリガー | 監査カテゴリ |
|---|---|---|---|---|---|
| `BoardOrchestratorAgent` | 役割1/2の中間出力を統合し、表示順・抑制・優先順位を制御 | `BoardPrepOutput` または `InMeetingOutput` 中間結果 | 優先順位付きアラート、要約、提示計画 | `severity` / `impact_score` / `confidence` / `owner_deadline_missing` | 既存カテゴリを再集約（High/Medium優先） |
| `EvidenceGatewayAgent` | 発言や論点の証跡ID解決、証拠不足の即時検知 | 生発言テキスト、`evidence_map` | `resolved`/`ambiguous`/`missing` 状態と根拠ID候補 | `evidence_id` 未解決・参照先不一致・期間母集団不一致 | `evidence_gap` / `definition_mismatch` |
| `FinancialCapitalOrchestrator` | 財務・資本観点を統合し、`capital_strategy_priority` を算出 | 各財務ワーカーの出力、会議文脈 | 財務観点の合成スコアと再計算要求 | `liquidity_runway_months`、`wacc_delta_bps`、`capital_structure_headroom`、`capital_allocation_value_score`、`downside_resilience_score` の閾値反応 | `financial_balance_breach` / `investment` |
| `PreBoardSynthesisAgent` | 会議前に議事録・未解決・RACI・期限を統合し、次回アジェンダ化 | 過去議事録、KPI、公開情報、`RACI`、`open_items` | `agenda_items` / `open_items` / `missing_info_requests` / `board_readiness_score` | 決定事項の未完了、期限不明、証拠未付与、外部シグナル未参照 | `owner_deadline_missing` / `evidence_gap` |
| `InMeetingCriticAgent` | 発言単位監査（前提・因果・期限・責任）を行い会議チャット向けに整形 | 発言、現在議題、直近会議文脈、コンテキスト証拠 | High/Medium/Lowアラート、`question`、`required_follow_up` | 断定/前提飛躍/期限欠如/責任未定義/定義不一致 | `evidence_gap` / `causal_leap` / `definition_mismatch` / `owner_deadline_missing` / `compliance_risk` |

### 2.2 財務・資本ワーカー

- `treasury-liquidity-worker`: 短中期の資金余力、13週〜12か月観点。
- `capital-markets-intel-worker`: 金利・資本市場・調達前提の更新、スプレッド変化。
- `capital-structure-worker`: 借換・満期集中・格付け余力・コベナンツ。
- `capital-allocation-worker`: 投資/還元/削減の優先順位と実行順。
- `investment-diligence-worker`: 投資案件のNPV/IRR/感度条件・再計算要件。
- `financial-risk-governance-worker`: リスク・統制・規制遵守・監査条件。
- `peer-benchmarking-worker`: 外部比較の乖離、外部シグナル未反映リスク（必要時のみ）。

### 2.3 各ワーカーの1行要約

1. `treasury-liquidity-worker`: 役割=資金ショート前兆の発見、入力=`TREAS-13W-2026-01` 等、出力=不足時刻・回避条件・`evidence_gap`。
2. `capital-markets-intel-worker`: 役割=資本コスト更新の監視、入力=`DEBT-2026-02`・金利系公開情報、出力=`wacc_delta_bps`前提の妥当性有無。
3. `capital-structure-worker`: 役割=借換や満期集中による余力圧迫監視、入力=`DEBT-2026-02`・`BS-2026-02`、出力=制約距離と警告。
4. `capital-allocation-worker`: 役割=配分意思決定の順番と根拠監査、入力=`CAPAL-2026-Q1`・`CF-2026-02`、出力=配分比較・条件分岐。
5. `investment-diligence-worker`: 役割=NPV/IRR/回収計算の欠損検知、入力=`CAPAL-2026-Q1`・`IS-2026-02`、出力=再計算条件。
6. `financial-risk-governance-worker`: 役割=監査同席・承認・契約制約違反を高優先検知、入力=`COMPLY-AUDIT-2026-Q1`・`PARTNER-LEGAL-2026`・`RACI-2026-Q1`、出力=`compliance_risk`。
7. `peer-benchmarking-worker`: 役割=外部とのずれの露出、入力=`PUB-NEWS-SMARTHR`・`SALES-ECON-2026-Q1`、出力=外部比較不足提示。

### 3.2 実行手順（PreBoardSynthesisAgent）

1. 過去議事録を時系列で読み、決定事項と未解決項目を抽出。
2. `minutes/meta` の会議IDとRACI、evidence参照を照合。
3. 外部シグナル（ニュース・市場）と社内KPIの整合を確認。
4. `agenda/` の起草ルールに従って次回アジェンダを優先順位付きで作成。
5. 未確定責任者・期限・不足情報を `missing_info_requests` に分離。
6. 各アジェンダ項目に `evidence_id` を最低1件付与。
7. `financial/compliance/market/governance` の観点で見落としを再確認し、最終稿を出力。

- 出力フォーマット想定: `agenda_items`、`open_items`、`missing_info_requests`、`linked_evidence` を必須で保有。

## 4. 会議中フロー（リアルタイム監査）

### 4.1 処理順

1. 発言入力（`speaker`/`timestamp`/`raw_text`/`normalized_text`）
2. `EvidenceGatewayAgent` で `evidence_id` 解決と証拠欠損検知
3. `InMeetingCriticAgent` が主張抽出とカテゴリ分類を実施
4. 財務関連語句を含む場合、財務・資本ワーカーへ振り分け
5. `FinancialCapitalOrchestrator` が財務観点を合成して `capital_strategy_priority` を補正
6. `BoardOrchestratorAgent` が最終制御（投稿上限・重複抑制・重要度順）

### 4.2 投稿可否ルール（最小版）

- `evidence_id` がない発言は原則 `evidence_gap`。
- 重要度判定は High/Medium/Low。最終的な投稿目安は1会議あたり最大5件（Highは必出）。
- 同一カテゴリの連続重複は、間隔5分以上や主張差分が無い場合は抑制。
- `owner_deadline_missing` / `compliance_risk` は抑制しにくく扱う。

### 4.3 Teams投稿に必須の要素

- 根拠: `evidence_id` と `evidence_source`
- 質問: `question`（短い確認質問）または `required_follow_up`
- 次アクション: `owner` / `deadline` / `next_action`

## 5. 財務・資本サブチーム詳細

### 5.1 観点別責務

- `liquidity`（資金余力）: `TREAS-13W-2026-01`、`CF-2026-02` を起点に `liquidity_runway_months` を監査。
- `capital_cost`（資本コスト）: `DEBT-2026-02` を起点に `wacc_delta_bps` と調達前提を監査。
- `capital_structure`（資本構成）: `DEBT-2026-02` を起点に満期集中・格付け余力を監査。
- `capital_allocation` / `investment`（資本配分・投資）: `CAPAL-2026-Q1` を起点に投資可否順序と再計算条件を監査。
- `downside_resilience`（下方耐性）: `definition_mismatch`/`compliance_risk` と連動し、ストレス耐性の実行可能性を監査。

### 5.2 `financial_strategy_priority` の合流先

- 各観点スコアは `FinancialCapitalOrchestrator` で統合され、`BoardOrchestratorAgent` の会議中提示優先度に渡される。
- 影響が高い場合は、会議内で複数回の疑義提起を許容。
- しきい値超過時は、`question` は「再計算条件」「実行順」「期限」まで具体化する。

## 6. 監査ルール・制約

- 数値定義（期間・母集団・単位）の不一致を疑う場合は、まず `definition_mismatch` を優先。
- 根拠が不明瞭な断定は必ず `evidence_gap` 経由にする。
- `owner_deadline_missing` と `compliance_risk` は高優先（抑制しにくい）。
- `question` または `required_follow_up` が欠けるアラートは再生成対象（Invalid扱い）。
- 根拠参照は `evidence_id` を先行し、`evidence_source` は必ず1件以上。
