# 2026-02-24 Prepare 用 会議エージェント設計書（v2.0）

## 1. 目的

- SmartHR想定会議素材に対して、会議前と会議中を分離した監査エージェントを運用する
- 会議前は `agenda_plus_facts` の品質最優先、会議中は `LowLatency` で的確に逸脱を投稿候補化
- SmartHRのダミーデータは **編集しない**

## 2. v2エージェント構成

| 層 | エージェント | 役割 |
| --- | --- | --- |
| 主役（会議前） | `MeetingPrepOrchestratorAgentV2` | 過去会議＋内部/公開情報を統合して `agenda_plus_facts` を生成 |
| 主役（会議中） | `InMeetingOrchestratorAgentV2` | 文字起こしを監査し、高精度な `logical_jump` と `premise_question` を生成 |
| 会議前サブ | `InternalInfoCollectorAgent` | 全会議ログ、KPI、RACI、財務、組織情報を吸い上げる |
| 会議前サブ | `PublicResearchAgent` | 公開情報（規制・景況・競合）を主張別に補完 |
| 会議前サブ | `FactCoverageReviewAgent` | 会議前成果物の `evidence_gap` を検出 |
| 会議前サブ | `MeetingPrepLeaderAgent` | `agenda_plus_facts` の重複排除、優先順位付け、出力整形 |
| 会議中サブ | `LogicalJumpCriticAgent` | 断定・因果飛躍・定義混在を検知 |
| 会議中サブ | `PremiseQuestionAgent` | `会議前ファクト` と `発言内容` の双方に「前提疑義」を生成 |
| 会議中サブ | `EvidenceGatewayAgent` | `evidence_id` を解決し、欠損時のみ追加確認を起動 |
| 会議中サブ | `FinanceCapitalEvidenceRoutingAgent` + 7ワーカー | 財務・資本ドメインに対して必要最小限ワーカーを起動 |

## 3. 参照順

### 会議前フロー

1. `board-meeting-index.json` から対象 `meeting_id` の素材を解決
2. `MeetingPrepOrchestratorAgentV2` へ `meeting_id` / `latest_minutes_id` / `target_minutes_candidates` を渡す
3. `InternalInfoCollectorAgent` + `PublicResearchAgent` でファクトを収集
4. `FactCoverageReviewAgent` が不足点を検知
5. `MeetingPrepLeaderAgent` が `agenda_plus_facts` を出力

### 会議中フロー

1. `InMeetingOrchestratorAgentV2` が `transcript_segment` を受け取り
2. `agenda_plus_facts` を参照して `LogicalJumpCriticAgent` / `PremiseQuestionAgent` を先行実行
3. 高リスク・不明確ケースのみ `EvidenceGatewayAgent` と Financeルータへ送る
4. Financeルータが7ワーカーへ必要分岐（5件を上限）
5. `action=post_if` を会議投稿候補へ、`hold_if` は保留
