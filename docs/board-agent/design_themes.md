# 取締役会アシストAgent 設計テーマ v1

## 1. 企画目的
- 取締役会の質を構造化し、議論の見落としと論理崩壊の再発率を下げる。
- 会議前準備（アジェンダ設計）と会議中監査（リアルタイム指摘）を、同じ論理基盤で運用する。

## 2. 設計テーマ

### 2.1 エビデンス優先設計
- 発言の真偽よりも、**証拠の存在性**と**論理の接続性**を優先評価。
- すべてのアラートは `evidence_id / source / confidence / 期待確認` を持つ。

### 2.2 汎用コア + 適応レイヤ
- 汎用コア: 議事抽出、論点優先度、監査ルール、アラート分類。
- 適応レイヤ: 企業特有のKPI定義、用語、規制優先順位、意思決定権限。
- 初期は `default_profile` のみで開始し、後に `industry_profile` / `company_profile` を重ねる。

### 2.3 会議前/会議中の双方向最適化
- 会議前で作成した「未解決項目」「追加情報要求」は、会議中監査のコンテキストに再利用。
- 会議中で検知した「証拠不足」「論点偏重」は会議後に次回アジェンダ候補へフィードバック。

### 2.4 監査可能性（Auditability）
- 収集データ、要約、判定、再生成の履歴をすべてトレース可能にする。
- 後から「なぜその指摘を出したか」を再現できることを最重要品質要件にする。

## 3. 監査ルールの基本カテゴリ
1. 根拠不足（Evidence Gap）
2. 因果飛躍（Causal Leap）
3. 指標定義不一致（Definition Mismatch）
4. 責任者／期限不足（Owner / Deadline Missing）
5. リスク未反映（Risk Omission）
6. 反対仮説不足（Counterfactual Gap）

## 4. 品質KPI（v1）
- 未解決議題が2件以上検知できること。
- 追加情報要求が3件以上生成されること。
- 必須5カテゴリのうち4カテゴリ以上を高確度で検知。
- 監査ログでアラート再現が100%可能であること。

## 5. 実装前の前提
- 本ドキュメントはv0.xとして公開。
- 初版は特定企業非依存データで作成。
- 次のリリースで業界・企業テンプレートを段階追加する。
